# Validation gates

These run in the `validate` stage, after `index` and before anything is selected, and again whenever a date or pairing is about to be written. They write flags; they never fix silently. Every one of them exists because the first run wrote something wrong that the gate would have caught, and the wrong thing then traveled downstream as a rule.

## Gates on dates and pairings

1. **Second witness for any join on a filename stem.** Camera counters repeat across phones and wrap every 10,000 shots; in a two-device household over a decade, collisions are guaranteed. A stem match may pair a Live Photo, inherit a date, or link an export to an original only if a second witness agrees: timestamps within a few seconds (EXIF versus container versus sidecar), the same camera make and model, or pixel similarity (perceptual hash for still-to-still; first-frame hash for a video half or an animation). Absent a witness, do not join, and flag `stem-collision`.

2. **Era plausibility.** Reject a settled date that the file could not have: HEIC or HEVC before 2017, a Live Photo before September 2015, and a camera model that did not exist in the claimed year, matched against a table of phone models by release year on an exact EXIF model string. The first run also read a resolution or a file size the era could not produce; that test is not in this version. Flag `era-implausible`, severity `block`. This gate alone would have caught three of the first run's five wrong dates, at zero cost.

3. **Prefix versus intact metadata.** If the settled date disagrees with the file's own intact EXIF or sidecar time, the row must name a specific witness (the matched file, the method, the distance). Flag `prefix-exif-disagree`. What the gate can enforce is that a witness is there: a date from a prior, a content match, the owner or a visual estimate that contradicts intact metadata is `block` while `date_witness` is empty and `warn` once it says anything at all, so the sentence reaches the sheet and the owner reads it. It cannot tell a named witness from an unverified story, so "re-export stamp" written into the witness downgrades the flag like any other sentence; only gate 7 reads a witness for its content, and only for a content match. Two intact sources that disagree with each other, a sidecar date against an EXIF capture time, are a `warn` from the start, because neither is the owner's claim.

4. **Live Photo pair validation.** The video half is 1 to 4 seconds long; its container creation time is within ±2 seconds of the still's capture time; the closest of the frames sampled across the clip is within 16 bits of the still on a 64-bit perceptual hash (the still is a key frame from inside the clip, so the first frame alone is not the witness; on real pairs the closest frame sits at 8 to 10 bits, unrelated frames at 22 or more). All three, or flag `pair-unverified` and treat the two files as separate items. The flag's evidence names all three in the order the index tried them: the clip's length, how far apart the two capture times are, and how many of 64 bits the closest sampled frame is from the still or, when that test never ran, why it did not (the duration gate failed first, the time gate failed first, ffmpeg was not available when the index ran, which is claimed only when the video's probe columns are all blank, or else ffmpeg could not read the clip, the still has no hash, or the index ran as a dry run, which the flag cannot tell apart). The suggested action follows the test that failed: for the missing tool, re-run the index with ffmpeg, because the frame test is the third witness and it never ran; for a clip of the wrong length or a frame that is not the still's scene, treat them as two separate items; for the time gate it has two branches, the seconds they are apart with `[project] timezone` in `config.toml` to check first when there is a delta, since a container time is UTC and a wrong zone is the usual reason two halves of one pair look hours apart, and, when one of the two carries no capture time so there is no delta to compare, to declare the pair with a witness if they belong together.

5. **Export title collisions.** When indexing a Takeout, key by member path, not by the title inside the sidecar; an export keeps the original title even when it renames the member with a `(1)` suffix. If two sidecars in one folder share a title, quarantine both from any automatic date or pairing decision. Flag `title-collision`.

6. **Owner corrections carry a confidence.** A date or fact supplied from memory is written with `date_source = owner` and a provisional mark until a second source agrees. On the first run, owner memory was right about a folder rule, a pinned photo and a recurring place, and wrong about the year of a trip; the fix was provenance, not distrust.

7. **"Content match" means a match ran.** The label is written only with the method and the distance recorded in the evidence. A hypothesis is written as a hypothesis, in the flags, not in the index. The gate is in the code and blocks a `content-match` row whose witness names no method and no distance, but nothing in this version writes `content-match`, so it never fires; it is the guard for the day the rung comes back.

8. **Age and era outliers on sheets.** For a whole-life show, a reviewer looking at composition will not notice that a child in one photo is ten years older than the rest of the page. Sort each period's sheet by estimated age, or highlight outliers, so the eye is drawn to them. Not in this version: the sheets mark date precision and nothing else, and `05-review-loop.md` says what a reviewer has instead.

9. **A modification stamp is not a capture time.** EXIF `DateTime` (tag 306) is written when a file is edited, re-exported or scanned, so a date taken from it is the edit or the scan date, not the day the picture was made. The index takes it only when nothing else answered, below the owner's priors, writes `date_source = exif-modified` and keeps the stamp out of `exif_datetime_original`, which carries only what the capture-class tags shipped, so nothing downstream reads the stamp as an intact capture time. Flag `exif-modified`, severity `warn`: confirm the date on the contact sheet, or declare it with a witness (`validate --resolve`). Gate 3 cannot fire on such a row, because no capture-class value on it parses into a date to disagree with.

10. **No date at all is a finding, not a silence.** A row that came out of the ladder with no date is flagged `undated`, severity `warn`, and the detail names the empty `date_source`, so the undated files are a list in `flags.csv` and not only a number in the index stage's summary. The suggested action is to find a witness: a sidecar, a matched original, or the owner's dated recollection marked provisional. Select cuts these files unless `--include-undated`, so the flag is where the owner sees them before that happens.

11. **A zeroed clock is not a date.** A camera whose battery died writes `0000:00:00 00:00:00`, a device that never had its clock set writes 1970, and a QuickTime container with no creation time writes 1904. Any of those in the EXIF, container or sidecar time is flagged `bogus-timestamp`, and the detail names which of the three carried it. It is a `warn` when the settled date came from somewhere else, with "ignore this timestamp; it is not a date" as the action, and a `block` when the settled date itself begins 1970 or 0000, where the action is to remove that date and run `index` again.

## Gates on the sources and the folder

12. **Copy, never move; quarantine, never delete; keep the export until after the event.** The first run deleted 163 GB of export zips the day integration finished, with 391 GB free, and lost the ability to re-check a pairing within the day.

13. **The working folder is not on a synced drive.** Warn at Step 0.

## Gates on the build side

14. **Verify derived sequences by content.** A frame sequence that is complete by count may be padded copies of one frame. Count distinct frames; a padding fallback fails past a small threshold and reports what it padded. Counting distinct frames is not in this version: `bin/frames` compares the number of files it wrote against the number the placement needs, pads a short tail with the last frame, reports any sequence it padded by more than three and fails past 30, so the loud fallback is there and the content check is not.

15. **Window renders around every special case.** Slow-motion clips, HDR clips, the longest videos, the loop wrap. A 60-second test render from the start of the loop covers nothing in the middle.

16. **The full watch.** The soak test measures dropped frames. Only a human watching the whole loop sees a frozen tile.

## What a flag looks like

`flags.csv`: `media_id, filename, gate, severity, detail, suggested_action, resolved_by, resolved_on`. Severity `block` stops the stage that depends on the value; `warn` goes to the sheets. Resolutions are dated changelog entries in the brief.
